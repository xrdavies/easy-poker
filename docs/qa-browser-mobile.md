日期：2026-09-13

## 结论

移动流程通过，未发现仍可复现的应用 UI 阻塞或越界。测试覆盖 `320×568`、`390×844`、`500×813`，另用 `844×390` 覆盖手机横屏高度。

## 已走通的流程

- 从移动大厅加入 HostA 创建的牌桌；无效短桌号/密码在客户端给出明确提示且不发请求。
- 坐下和补码弹层只暴露弹层自身控件，底层牌桌控件不能点击或聚焦。
- 双玩家实战完成加注、跟注、过牌、弃牌、全下、发牌次数投票、单/双牌面结算。
- `320×568` 下加注滑条与动作按钮分两行，最后一行底边为 566px，无重叠或裁切。
- `500×813` 下操作栏保持单行；公共牌、座位、底牌和状态区互不覆盖。
- 8 玩家最终结算在 `320×568` 下完整显示，昵称与数值列不串列，按钮宽度自适应。
- 键盘 Space 可触发坐下、买入和动作；Tab 顺序为顶栏后按动作行从左到右。

## 本轮发现并修复

- `320×568` 大厅底部裁切；短视口改用原生滚动。
- “摊牌结算中”覆盖底牌；状态提示移到独立底部条。
- 小屏空座位遮住公共牌；最窄屏不绘制无交互价值的空座位。
- 动作第二行越界 2px；短屏行距调整后底边稳定在视口内。
- 中央规则、倒计时、下注筹码和徽章互相覆盖；窄屏省略重复规则行并重新分配中心区域。
- 双牌面玩家结果、缩略底牌和赢家行重叠；增加内容间距并按视口压缩牌面。
- 全下后立即点“发两次”会被 800ms 动作锁吞掉；进入投票快照时解除上一阶段动作锁。
- 页面加载即创建 AudioContext；改为先下载原始音频，只在 pointer/keyboard 用户手势中创建并解码。
