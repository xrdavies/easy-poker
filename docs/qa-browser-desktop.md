## 结论

桌面与矮横屏流程通过，未发现仍可复现的应用 UI 阻塞或越界。测试覆盖 `1440×900`、`1024×768`、`800×600`、`844×390`。

## 已走通的流程

- 大厅创建/加入标签、昵称、随机名、游戏时长、最大买入和三个规则开关。
- 创建牌桌、复制邀请、坐下、买入、起身、重新坐下、退出。
- 双玩家实战：加注滑条、加注、跟注、过牌、弃牌、全下、超时、各公共牌街。
- 全下后两端选择“发两次”，服务端返回两组各 5 张公共牌；单牌面和双牌面结算均检查。
- 补码先显示 pending，下一手到账。
- 8 玩家最终桌结算在 `844×390` 下完整显示，两个底部按钮不重叠且均在视口内。
- 原生语义按钮可用键盘操作；Tab 顺序按视觉位置排列。Canvas 有场景描述，toast 使用 live status。

## 本轮发现并修复

- `800×600` 被错误当成竖屏；现在只按真实方向选择布局。
- `844×390` 大厅无法滚动；短视口大厅现在保留 700px 画布并使用原生页面滚动。
- 矮横屏牌桌顶进工具栏、中心元素堆叠；现在使用扁桌、单行动作栏、小公共牌和侧置底池信息。
- 庄位/盲注徽章压头像；徽章改为成组布局，矮横屏移到头像侧面。
- 双牌面结算内容溢出面板；面板改按视口与内容高度布局，结算态隐藏被遮挡的顶栏控件和底牌。
- 起身后结算昵称退化为 UUID；昵称查找同时覆盖座位和观战列表。
- 游戏时长伪下拉难以理解；改为明确的前后切换按钮并提供完整无障碍名称。
